# 任课老师调整

管理员进入「任课老师关联」，找到对应班级和学科，点击「调整老师」，选择接任老师并确认。可填写调整原因，成功后显示已交接的方案数量。列表支持按班级、学科、老师和账号搜索，窄屏以逐条列表展示。

## 交接范围

- 保持原班级、学科不变，更换该条任课关联的老师。
- 接任人须为已启用的任课老师或班主任账号；班主任以兼课身份接任，不改变班主任归属。
- 将该班启用周期中、未归档档案内，同学科且由原老师负责的学科方案交接给接任人，保留正文与状态。
- 其他老师的学生专属安排、其他班级和学科、已归档档案、停用周期、版本快照、历史月评内容与署名保持原样。
- 德育和班主任关联不能通过此入口调整。
- 接任人立即取得该班关联及交接方案的权限。可填写方案使用既有分配待办机制，Web 与小程序均可收到提醒；档案原有状态和填写限制继续生效。

## 接口与审计

`PUT /api/admin/class-teacher-links/{link_id}`，仅管理员可用：

```json
{
  "teacher_id": 102,
  "previous_teacher_id": 101,
  "reason": "教学安排调整"
}
```

返回更新后的任课关联及 `updated_plans`。原老师已变化或目标老师已关联同班同科时返回 409；不接受停用或非教师账号。

任课关联和方案在同一事务中写入，失败整体回滚。关联记录 `class_teacher.adjusted`，每份方案沿用 `subject_plan.assigned`，审计包含操作者、原老师、接任老师、班级、学科、原因和方案 ID。班级、档案及方案锁与调班流程协调，过期页面通过 `previous_teacher_id` 拒绝覆盖后续调整。

## 验证

- `backend/tests/test_teacher_adjustment.py`：交接范围、历史与正文保留、接任权限及待办、管理员限制、停用账号与重复关系、过期请求、整体回滚、并发调整。
- `backend/tests/test_subject_teacher.py`：原有分配、填写、待办和权限回归。
- `output/verify_teacher_adjustment_20261022.cjs`：使用模拟 API，在 1440、375、320px 下检查选择、搜索、分页名单、冲突、重试和成功回显，无真实业务写入。

后端验证使用独立测试 schema；浏览器模拟 API 与业务数据库隔离。本功能无需数据库迁移。
