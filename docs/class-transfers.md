# 同年级批量调班

操作权限仅限 `admin`（管理员/校长）和 `deyu_director`（德育主任）。预览、提交和记录查询均在后端校验角色，班主任、任课老师、咨询老师及家长/学生不能调用。

## 使用方法

Web：班级与教学组织 → 批量调班。小程序：班级管理 → 批量调班。

1. 先配置目标班级的班主任与各科任课关系。
2. 选择原班级，展示学生名单；勾选一名或多名学生，再选择目标班级并加入调班名单。
3. 点击预览，核对学生姓名、原班/新班、人数变化和交接异常。目标班同科存在多名老师时，必须指定接手人并重新预览；没有任课老师时先补齐班级任课关系。
4. 填写调班原因，确认后立即生效；在调班记录中查阅批次、操作人和学生去向。

每批最多 500 人。学生身份由已选班级名单中的学号确定。

## 交接规则

- 仅移除明确指定的原班关系，保留独立的 1V1 或其他课程班关系。
- 学号、登录身份、家长和咨询老师关联保留。
- 同学年活动周期内的未归档档案转交目标班主任，科目内容、任务、打卡和既有版本保留；德育归新班主任，其他学科归目标班确认的任课老师；未结束的整改审查同步转交。
- 已归档或已结束周期的档案保留原归属。新班主任可按学生及调班记录读取原班历史。
- 历史成绩保留原班级，同时冻结调班前的初评选科口径，防止旧成绩汇总和排名因档案移动而丢失。
- 已结束周期的积分报表保留原班与积分；按历史周/月重新生成时还原当期名单并保留已有报表，防止移班后覆盖旧积分。
- 过去月份、已发布月评保留原班及作者并变为只读。当月及未来未发布月评移交新班继续完成，原文与评价作者保留。原老师提交的科目内容仍计作已填写；新老师续写时保留原评价。
- 当月已发布的原班月评仍计入该生本月成果，避免新班重复催填、重复建月评。过去月份的名单与责任通过交接快照还原。
- 原班、目标班已有同生同月月评时阻止提交，不自动合并内容。
- “添加已有学生”不能再将同一学生重复加入同类班级；调班必须走专用入口。

## 一致性及发布

预览不写业务数据。提交使用学生、班级、档案及月评锁，并比对预览摘要；资料变化后要求重新预览。全部交接与审计在同一事务中提交，任一失败则回滚整批。相同提交编号和相同内容的重试返回原批次，不重复执行。

迁移版本：`e3f4a5b6c7d8`，前置版本：`d2e3f4a5b6c7`。发布前备份数据库，在后端目录执行 `alembic upgrade head`，再发布后端、Web 和小程序。不要把独立测试 API 指向 `public`；自动化测试使用隔离 schema。

迁移新增调班批次/明细表及成绩选科快照字段；不批量改动现有学生名单。上线后先预览实际名单，核对再提交。调班后发生了新的教学记录时，纠正名单应建立反向调班批次，保留完整审计。
